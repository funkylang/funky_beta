# llama::TOP_P (a unique item)

  the top-p option for llama-server completion requests

  Use as a key in the options of <llama::complete> to set the nucleus sampling
  threshold. Only the smallest set of tokens whose probabilities sum to at least
  TOP_P are considered; all other tokens are discarded before sampling occurs.
  This is a probability-based filter: when the model is confident, fewer tokens
  survive; when it's uncertain, more tokens remain in play.

  Consider a single selection step where the model assigns these probabilities
  after softmax:

    "the" : 60 percent   (highest)
    "a"   : 25 percent
    "an"  : 10 percent
    "this": 5 percent
    "that": 3 percent
    "its" : 1 percent

  With TOP_P = 0.9: start with the highest probability and walk downward,
  adding tokens until the sum reaches 0.9 (90 percent):

    - 60 (the)
    - 85 (a)
    - 95 (an)

  Now we hit 95 percent after three tokens, which exceeds 90 percent. Only
  "the", "a", and "an" are considered; the remaining tokens are discarded.

  With TOP_P = 0.95: same walk, but we stop once the sum reaches
  95 percent:

    - 60 (the)
    - 85 (a)
    - 95 (an)

  We reach 95 percent exactly with three tokens; they are the only candidates.

  With TOP_P = 0.99: now we need 99 percent:

    - 60 (the)
    - 85 (a)
    - 95 (an)
    - 100 (this)

  Now four tokens are in play; "this" has a real chance.

  TOP_P adapts dynamically: when the model assigns one token a very high
  probability, only that token remains. When probabilities are spread across
  many tokens, more of them stay available for sampling. This prevents sampling
  from the unlikely tail while allowing diverse choices among strong candidates.

      TEMPERATURE = 1.0
