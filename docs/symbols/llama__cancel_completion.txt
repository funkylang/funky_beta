# llama::cancel_completion (a function)

  cancels a streaming llama-server completion

  Parameters:
    io: the io object the stream is running on
    user_id: the identifier supplied when starting the completion

  Result:
    the updated io object, or an error object if no stream matches

  Cancels a completion that was started with the io-object version of
  llama::complete. The application receives no event for this cancellation:
  no CLOSED or READ_FAILED arrives under the user_id, because only the server
  closing the connection produces such an event. The completion stops on the
  server as soon as it notices the closed connection.

  On success the function returns the updated io object with the
  cancellation already scheduled. If the io object does not carry a stream
  for the given identifier, it instead returns an error object and no stream
  is touched.

  Topic: AI

  See also: std_types::io/llama::complete, std::CLOSED

  Example:

    <require basic/stdlib>
    <require ai/llama_server>

    <using std>

    # The user id for this stream.
    $COMPLETE_STREAM .

    # Token counter state: one object; its count is updated in the app handler
    # and read back by cancel_decide, which checks the cancellation condition.
    $tokens_received_of ()
    $stream_state std_types::object
      .tokens_received_of 0

    # Cancel after this many tokens.
    $token_limit 2

    do:
      $io std_types::io
      $state stream_state

      initialize! &io

      # Count to one hundred - long enough generation to be cancellable.
      llama::complete &io COMPLETE_STREAM "/no_think/Count from 1 to 100."
        llama::MAX_TOKENS = 100

      loop:
        get_events! &io $events
        handle_events &io &events
        # Dispatch the leftover events to the application handlers
        handle_application_events &io &state events
        next!

    # On every READ event, count the token and cancel when the limit is
    # reached. No CLOSED handler is needed: canceling a stream never produces
    # one - only the server closing its end does.

    $handle_application_events: (io state events)
      for_each events
        : (event)
          event $type $id $data
          if
	    id != COMPLETE_STREAM
	    :
	      next!
	    :
	      case type
	        READ:
	          print_to &io STDOUT_FILENO data
	          !state state(.tokens_received_of (tokens_received_of(state)+1))
	          cancel_decide &io state
	          next!
	        :
	          # Infrastructure events (fd ids) - not for the application
	          next!
        : -> io state

    # Decides whether the token limit is reached and cancels in that case.
    # Called with I/O-access rights by the handler above; io is rebound via &
    # so the cancelled connection's close job survives to get_events.

    $cancel_decide: (io state)
      if
        tokens_received_of(state) >= token_limit
        :
          $count tokens_received_of(state)
          $note "@nl;[cancel after @(count) tokens]@nl;"
          print_to &io STDOUT_FILENO note
          llama::cancel_completion &io COMPLETE_STREAM
          exit &io
          -> io
        :
          -> io
